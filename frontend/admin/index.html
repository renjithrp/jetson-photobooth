Google Drive

One-time setup: in Google Cloud Console create an OAuth Web application client, add the redirect URI below to it, then paste the Client ID + Secret here, Save, and click Connect. Google's guide: create a Client ID & Secret →

Step-by-step: get a Client ID & Secret
  1. Open Google Cloud Console → Credentials (create a project if asked).
  2. Enable the Google Drive API for that project.
  3. On OAuth consent screen: choose External and add your own Google account under Test users.
  4. Create Credentials → OAuth client ID → application type Web application.
  5. Under Authorized redirect URIs add the exact URI shown below (re-add it if the booth's IP ever changes).
  6. Copy the Client ID + Secret into the fields here → Save → Connect Google Drive. Google will show an "unverified app" warning because your client hasn't been through review — first check the app name on the consent screen is the one you just created, then continue via "Advanced". Never do this for a consent screen you didn't initiate from this page.

Amazon S3

Amazon S3 or any S3-compatible store (Wasabi, Backblaze B2, Cloudflare R2, MinIO). AWS guide: create access keys →

Step-by-step: get an Access key ID & Secret (AWS)
  1. Create an S3 bucket (note its name and region for the fields above).
  2. In IAM → Users, create a user just for the booth (no console access) and attach a policy limited to this bucket only (example policy). Don't grant account-wide S3 access — this key is stored on the booth, so scoping it limits the damage if the booth is ever compromised.
  3. Open the user → Security credentials → Create access key (use case: "Application running outside AWS").
  4. Copy the Access key ID and Secret access key into the fields here — the secret is shown only once — then Save and Test.

Wasabi / B2 / R2 / MinIO: create keys in that provider's console instead, set Provider (e.g. Cloudflare, Wasabi, Minio) and its Endpoint URL.
